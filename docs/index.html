00excel-table-bot

A 3,000-row spreadsheet, and the model never reads a row.

Ask it to total a column and it does not add the numbers up. It calls a function that adds them up, and reports what came back. The file can be 40 columns wide and the answer still costs one turn.

excel-table-bot is a Telegram assistant for spreadsheets: send a file, talk to it, get it back. Everything a language model is good at — understanding "merge these two price lists by article" — it does. Everything it is bad at — arithmetic over three thousand rows — it delegates.

01the collapse

Thirteen nodes, one agent

The predecessor was an n8n workflow: three hard-coded modes, thirteen code nodes, and a redis state machine to remember which step of which mode a chat was in. Adding a fourth thing you could ask meant a fourth branch.

02the division

The model decides. Python counts.

This is the whole discipline, and it is what keeps a wide file usable. The agent chooses which range matters. It never sees the rows in that range, so it cannot get tired, cannot lose a digit, and cannot turn three thousand rows into three thousand tokens.

03the join

The model is the last resort, not the first

Comparing two price lists means matching keys that humans typed differently. Three tiers run in order, and each one only sees what the tier above could not solve. The model is tier three — reached last, on the smallest set, and never trusted on the way out.

04real files

Spreadsheets people actually send

A real file does not start with a header. It starts with a company name, an export date, a blank row, and then the header — sometimes with gaps in it.

Everything is normalised to one workbook object on load, so the rest of the bot never learns that .xls exists. The scoring heuristic is inherited from the n8n version — it was the one piece worth carrying over unchanged.

05the scar

The buttons that fell into the model

The n8n original had a persistent keyboard: a help page and an RU/ENG switch. The Python rewrite dropped it, and the buttons did not stop working loudly — they stopped working quietly. A press became just another sentence, and the CRUD agent did its best with "Помощь".

the failure mode
a button press is indistinguishable from a request
— the fix —
classify_button() runs first; a press never reaches the model

Worth writing down because it is the failure mode of every agent front-end: once anything can be a prompt, everything becomes one. The boundary has to be drawn on purpose, before the model is called.

06staying up

One file per chat, and a restart nobody notices

Each chat has at most one working file. Redis holds the path and the reply filename — not the workbook, and not the conversation. The heavy object stays on disk.

A failed turnlogged and reported, never fatal

A transient OpenAI or file error ends that turn and nothing else. The long-poll process is not something a bad spreadsheet gets to kill.

07structure

One process, three ways in, one file out

The router is the only thing that reads a message. What it decides first is whether the message is a button — because a button must never become a prompt — and only then whether the rest is a sentence for the agent or a step in a wizard.
